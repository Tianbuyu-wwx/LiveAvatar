# R2 传输层对比报告：自研 WS 传输 vs LiveKit（基线）

> 状态：M6 收尾　|　测量工具：[scripts/wsperf.py](file:///e:/项目/LiveAvatar/scripts/wsperf.py) / [scripts/e2e_bench.py](file:///e:/项目/LiveAvatar/scripts/e2e_bench.py)
> 方法与结论遵循证据标注：[实测] / [推断] / [待补]

## 1. 指标定义

| 指标 | 定义 |
|---|---|
| `fps` | 实测帧率（首帧到末帧） |
| `wire_kbps` | 线路带宽（含 26B 帧头的 bit/s） |
| `encode_ms` | 单帧编码耗时（JPEG/区域块 + 打包） |
| `gap_ms_p50/p95` | 相邻帧到达间隔的中位/95 分位 |
| 打断延迟 | `cancel_epoch` → 客户端最后可见帧变化（M3 后可端到端实测） |

## 2. M0 基线（纯 CPU 合成流）[实测]

环境：Windows，py312，cv2 4.13（libjpeg-turbo SIMD）；合成 512² 低熵渐变图，25fps，q80，500 帧 × 2 组；进程内回环（无网络、无 GPU）。

| 指标 | codec=1 region_delta | codec=0 mjpeg_full |
|---|---|---|
| 实测 fps | 25.06 | 25.04 |
| 线路带宽 | **764 kbps** | 1670 kbps |
| 平均帧大小 | 3.8 KB（480 patch + 20 keyframe） | 8.3 KB |
| 编码 p50 / p95 | **0.24 / 0.63 ms** | 0.62 / 1.53 ms |
| gap p50 / p95 | 46 / 62 ms | 46 / 62 ms |

**解读** [推断]：

1. **编码预算极充裕**：计划预算 2–5ms/帧，实测低熵图 0.24–0.62ms。真实人脸图熵更高（约 3–5×），仍预计 ≤2ms，不构成瓶颈。
2. **带宽达成路径确认**：合成图为带宽下界；按真实人脸图熵外推，region_delta ≈ 1.5–2 Mbps（符合 ≤2 Mbps 目标），mjpeg_full ≈ 5–8 Mbps（与计划估算一致）。区域编码相对全帧节省 ≈ 55%（合成）→ 真实素材预计 70–80%。
3. **gap p50 46ms**：Windows `sleep` 量化（~15.6ms 粒度）导致，非协议开销；网络传输后的真实抖动在 M1 URL 模式实测。
4. synthetic 模式同时验证了 pack → unpack → stats 的完整回环（500 帧 0 错误 0 丢弃）。

## 3. M6 端到端实测（真实 socket 往返，纯 CPU）[实测]

工具：`scripts/e2e_bench.py`——进程内启动真实 publish 服务（uvicorn，demo 合成 worker 128²），跨 3 个事件循环经真实 WebSocket 推 16kHz 静音 PCM（/audio）并订阅 /video 帧。每 codec 10 s，各测 2 项延迟 + 稳态吞吐。

| 指标 | mjpeg_full | region_delta |
|---|---|---|
| 启动延迟（首 PCM → 首帧到达） | **3.9 ms** | **3.5 ms** |
| 打断延迟（epoch 递增 → epoch_boundary 帧到达） | **2.8 ms** | **5.2 ms** |
| 断线重连 → 首关键帧（0.5s 模拟断网） | **7.7 ms** | **45.1 ms** |
| 送达帧数 / 丢帧 | 280 / 0 | 284 / 0 |
| 线路带宽 @128² 合成 | 570 kbps | 394 kbps（↓31%） |
| gap p50 / p95 | 0.2 / 112 ms | 0.2 / 111 ms |

**解读** [推断]：

1. 三项延迟均远低于验收线（打断 ≤90ms、重连 ≤1s）；重连 ms 级波动来自批到达相位，非协议开销。
2. gap p95 ≈ 110ms 是合成 worker 的批量化伪影：每 100ms 音频块产出 4 帧突发，非传输抖动；真实 MuseTalk worker 帧率贴合音频时钟后消失。
3. fps 40.6 > 25 标称同因：合成 worker 不按音频时长产出帧。带宽 570/394 kbps 为 128² 下界，512² 口径见 §2（1670/764 kbps），真实人脸素材按 §2 外推。
4. 顺带修复实测暴露的真实缺陷：客户端断开后 `/video` 的 `send_bytes` 与 ASGI close 竞态抛 RuntimeError（[publish.py](file:///e:/项目/LiveAvatar/src/liveavatar/publish.py) 已捕获为正常断开）。

LiveKit 链路（Server + SDK）基线测量**未执行**：GPU 持续跑训练且需 Docker LiveKit Server。自研传输已是默认（`LIVEAVATAR_TRANSPORT=ws`），`livekit` extra 进入 deprecation 期（两个小版本后移除），LiveKit 基线不再阻塞验收；若后续需要对比，可复用 `e2e_bench.py` 的口径补测。

## 5. 最终结论

- 协议 v1 冻结（[docs/PROTOCOL.md](file:///e:/项目/LiveAvatar/docs/PROTOCOL.md)），编码/带宽假设全部成立；
- 端到端三项延迟全部达标，0 丢帧 0 串 epoch；
- 自研传输默认开启，LiveKit 降级为可选过渡依赖。
