## 一、结论先行

**v3 的 16 项绑定中，工程面自研已基本收割完毕。** 本轮实测复核后：

1. **v3 的 R1'/R2' 清理项全部落地**（证据见 §二）：diffusers / transformers / websockets / PIL 已从推理路径清除，LiveKit 已删除，GPT-SoVITS V-A 收编声明完成，P0 gitignore 缺陷已修复。
2. **当前剩余绑定只有 4 类**：
   - **模型权重墙**（❌ 训练墙，唯一解是 R3 自训）：GPT-SoVITS 全家桶 ~1.4GB、MuseTalk unet.pth、sd-vae-ft-mse、whisper-tiny、YuNet 过渡权重；
   - **基石库**（❌ 自研有害无益）：numpy / torch / opencv；
   - **框架层**（⚠️ 可自研但不建议）：fastapi + uvicorn、pydantic 系；
   - **两个小尾巴**（🆕 本次新发现 / 可低成本收尾）：`httpx2`（LLM spoke 运行时引用）、V-B 引擎收编（纯整理）。
3. **新发现一处 v3 未覆盖的绑定点**：[text_source.py](file:///e:/项目/LiveAvatar/src/liveavatar/text_source.py#L129) 的 OpenAI 兼容 LLM spoke 在运行时 `import httpx2`，而 httpx2 只在 `dev` extras 中 —— 生产环境启用 LLM spoke 会 ImportError。P2 级，10 分钟可修（方案 a）。
4. **总体判定**："全换成自己写的" 在**代码意义上已达成约 90%**（传输、协议、编解码、TTS/口型封装、音频输入链、可观测性、鉴权、web 前端、人脸模型全部自研）；剩余的不可替换物是**模型权重**（只能训练不能"写"）和**基石库**（自研会直接劣化主体功能）。在那之前，权重按资源管理、代码按自有管理，主体功能全程可用。

## 三、逐项可行性分析（当前剩余绑定面）

### 3.1 GPT-SoVITS 引擎代码 —— ⚠️ V-A 已完成，V-B 收编待做（纯整理，无功能收益）

**绑定面 [实测]**：唯一入口 [voice/pool.py](file:///e:/项目/LiveAvatar/src/liveavatar/voice/pool.py#L173-L181) `sys.path` 注入 + `from GPT_SoVITS.TTS_infer_pack.TTS import TTS, TTS_Config`；引擎 vendored 于 `third_party/GPT_SoVITS/`（MIT，已含 README_SELF.md 收编声明，commit 69e693c）。

- **V-A 维持 vendored + 声明**：✅ 已完成。
- **V-B 迁入 `src/liveavatar/tts_engine/`**（裁剪 webui/训练代码、包内 import、去 sys.path hack）：⚠️ 可行，1–2 周，行为零变化，收益是品牌/整洁而非去依赖。引擎内部仍依赖 transformers/einops/librosa/torchaudio（`[实测]` TTS.py:10/19/31），故 `tts` extras 必须保留。
- **V-C 自研 TTS**：❌ 不立项（中文文本前端 + 少样本克隆声学模型是数月训练工程，质量回退风险大）。

**结论**：V-B 随 R2'' 顺手做或永久搁置；不影响主体功能。

### 3.2 GPT-SoVITS 基础权重（~1.4GB）—— ❌ 训练墙

chinese-hubert-base / roberta-wwm-ext-large / s1v3.ckpt / v2Pro / eres2netv2 / fasttext lid.176.bin。预训练模型无法"写"出来，只能训练（数月 + 多卡）或保留。**按资源管理**（`scripts/download_gptsovits.py` 拉取），主体功能 100% 可用。角色权重本就是自训/自采资产，不算绑定。

### 3.3 MuseTalk unet.pth + sd-vae-ft-mse + whisper-tiny 权重 —— ⚠️ R3 自训线（库依赖已剥离完毕）

**v4 变化**：v3 时"模型+库"混在一起评 ⚠️；现在**库已全部自研**（§二），只剩权重本体。解法不变：R3 自训口型模型（1–2 月 + GPU，第二个 AvatarWorker 接入，A/B 达标后才切默认）。权重缺失时已有 static_worker / fake 链路兜底，主体功能不中断。

### 3.4 MediaPipe 教师模型 + OpenCV YuNet —— ❌→⚠️ R1 在途（过渡期 legacy 保功能）

- **mediapipe**：`[实测]` 运行路径仅剩 [face_backend.py](file:///e:/项目/LiveAvatar/src/liveavatar/face_backend.py#L367-L406) 的 legacy 后端（可选探针，未装则跳过）；训练脚本 make_face_dataset / face_align 用作教师。`teacher` extra 独立，CI light 环境零绑定。✅ 隔离完成。
- **YuNet（cv2.FaceDetectorYN）**：当前**默认后端**仍是 v1det + landmarks5_192_v2（用户 09-02 拍板）。自研 v3b/v3c 线已归档 opt-in；剩余 GPU 清单：素材扩充 → M2 再训 → M4 真实验收 → 默认切换 → 过渡 2 个 minor 后删 legacy。
- **评级**：❌→⚠️（自训可行、已在执行，过渡期 legacy 保证主体功能 100%）。

### 3.5 ffmpeg —— ⚠️ 已可选化，保留二进制（不可自研）

`[实测]` src/ 内仅 [sinks.py](file:///e:/项目/LiveAvatar/src/liveavatar/sinks.py#L55-L109) `RtmpSink` 通过 subprocess stdin 喂 BGR24 原始帧（无 Python 依赖，PATH 上需 ffmpeg 二进制）。主分发路径是自研 WS sink，RTMP 是可选插件（commit 69e693c 已文档化）。视频编码器/容器复用器自研无价值。**保留，评级 ⚠️（非主体）**。

### 3.6 fastapi + uvicorn —— ⚠️ 可行但不建议（v3 结论维持）

**绑定面 [实测]**：[publish/](file:///e:/项目/LiveAvatar/src/liveavatar/publish) 包 —— REST ~6 端点 + 2 WS + StaticFiles + /metrics。自研微 ASGI 路由 1–2 周可行（项目已有 receive-loop、RFC6455 服务端+客户端经验），测试网（648 用例）可承接回归。但收益仅是 pip 安装面，风险是 WS/HTTP 语义长尾兼容。**维持：不立项**；publish/ 已模块化，将来真要切，切换面可控。

### 3.7 pydantic / pydantic-settings —— ⚠️ 不做（v3 结论维持）

`[实测]` 用于 config.py / voice/config.py 校验 + API models。dataclass + 手写校验 ~1 周，收益低、长尾 bug 风险高。**保留**。

### 3.8 httpx2（LLM spoke）—— 🆕 新发现，✅ 低成本可解决

**绑定面 [实测]**：[text_source.py:129](file:///e:/项目/LiveAvatar/src/liveavatar/text_source.py#L129) `import httpx2 as httpx`（函数内惰性导入），用于 OpenAI 兼容 `/chat/completions` SSE 流式；httpx2 仅在 `dev` extras。e2e_bench / capacity_report 也用（dev 场景，无碍）。**v3 报告未覆盖此项**（duplex spokes 与 v3 同日落码）。

- **方案 a（推荐，10 分钟）**：pyproject 增加 `llm = ["httpx2"]` extra，文档声明 LLM spoke 需装；零代码改动，惰性导入已保证其他路径不受影响。
- **方案 b（可选，1–2 天）**：自研流式 HTTP/1.1 客户端（asyncio + ssl + SSE 行解析，~300 行）替换 httpx2 —— 已有 RFC6455 自研客户端同构经验，需 TLS/超时/代理边界测试 + 真实端点 e2e 验证。
- **结论**：✅ 方案 a 立即做；方案 b 列入 R2'' 可选（完成全自研版图的最后一块）。

### 3.9 opencv (cv2) —— ❌ 保留

`[实测]` 运行路径：ws_sink/preview/region_codec/musetalk_worker 的图像 IO、resize、BGR↔RGB、JPEG 编解码；离线工具：prepare_avatar / face_accept / 批处理。FaceDetectorYN（YuNet 载体）与 videoio 无自研价值；基础算子 numpy 化慢 5–10×，直接劣化视频管线。**保留**。

### 3.10 numpy / torch / torchvision —— ❌ 基石，保留

全项目数值内核与 GPU 推理运行时，自研不现实也无意义。

### 3.11 einops —— ⚠️ 保留（third_party 引擎内部依赖）

`[实测]` 仅 `third_party/GPT_SoVITS/module/core_vq.py` 使用（v3 勘误后确认是真实依赖），inference extras 已不含（commit 8ad403e），仅在 `tts` extras。自研薄层无意义。

### 3.12 dev 工具链（pytest / pytest-cov / pytest-timeout / httpx2 / websockets / ruff / mypy）—— ❌ 非主体，保留

质量门禁工具，无自研价值。tests 内 `import websockets` 用于 WS 压测/回归 fixtures，不影响运行时自研终态。

### 3.13 web 前端 —— ✅ 已是自研终态

`[实测]` web/ 三文件零外部依赖（无 CDN、无框架、无构建链）。

### 4.2 分阶段路线（v4）

- **R2''（立即可做，CPU-only，合计 ≤2 小时 + 可选项 1–2 天）**

  2. （可选）自研流式 HTTP 客户端替换 httpx2（§3.8 方案 b）；
  3. （可选，纯整理）GPT-SoVITS V-B 收编 `src/liveavatar/tts_engine/`（§3.1）。
- **R1 GPU 清单（在途，等 GPU 窗口）**：素材扩充 + M2 再训（v3 线 det_conf 0.35 口径）→ M4 真实验收 → 默认后端切自研 → 过渡 2 个 minor 删 legacy/mediapipe teacher。

- **明确不做**：fastapi/pydantic/opencv/numpy/torch/dev 工具链的自研替换。

### 4.3 主体功能验收标准（每阶段全量执行）

1. **核心链路**：文本/音频进 → TTS（vendored GPT-SoVITS + 自训角色权重）→ 口型视频（MuseTalk 权重 + 自研推理代码）→ 浏览器（自研 web + WS 协议）实时观看，模式 B 8s 音频 → 200 帧 0 丢帧；
2. **实时性**：全双工会话 epoch 打断 TTS ≤1 chunk / 视频 ≤1 帧，打断延迟 ≤90ms（基线实测 2.8–5.2ms）；
3. **并发与隔离**：3-way 并发 + VoicePool 租约隔离 + 降级链触发与恢复；
4. **安全与观测**：HS256 session_token 鉴权、/metrics、trace-id 日志；
5. **质量门禁**：全量 pytest + ruff + mypy + coverage ≥83% 全绿，CI 3.10/3.11/3.12 矩阵通过；
6. **许可维度**：in-repo 代码 AGPL-3.0-or-later（commit 502d67f），vendored 引擎 MIT，mediapipe Apache-2.0 —— 自研面扩大后许可自主权同步扩大（商业化排除项由用户自设，非上游约束）。
