## 三、各阶段详细设计

### P-A 五层打断时间线打点 + 硬切基线（当前系统的"诚实画像"）

**开发内容**
1. 打点框架扩展（`observability.py` + `duplex.py`）：打断事件发布后，在五个关键点记录单调时钟时间戳：
   - `L1_detect`（ASR/VAD 判定打断，audio_in 已有 EOU）
   - `L2_tts_stop`（NvcWorker CancelToken 生效、TTS 停止）
   - `L3_audio_flush`（已合成 PCM chunk 丢弃完成）
   - `L4_video_invalidate`（epoch+1 广播、旧帧失效，`ws_sink`）
   - `L5_first_new_frame`（新语句/过渡帧首帧到达客户端）
2. 打断延迟分解：`L5-L1` 全链路 + 各层增量，进 `/metrics` 与离线 JSON。
3. **硬切基线数据集**：3 素材（不同说话人/语速）× 20 个打断点（均匀 + 随机种子固定），录制"音频进 → 打断 → 恢复"完整音视频（客户端侧录制，`preview`/wsperf 改造）。

**验证门禁**：输出 `docs/打断延迟分解_*.md`（五层 p50/p95 表）；对 3 组数据帧差分析确认硬切伪影客观存在（打断点前后口型突变帧差显著高于正常帧间差）。

**产出 → 论文 Section 5.1（实测分解表）+ 所有实验的数据基础设施。**

### P-B 评测管线 + V-APT 指标库（论文的度量贡献）

**指标定义（写论文前先用代码钉死）**
1. **V-APT**（Visual Average Penalty Time）：∫ w(t)dt，t ∈ [t_int, t_recover]；w(t)=1 当嘴部运动能量曲线出现"非自然扰动"（半口型僵持/大跳变），t_recover 为曲线回归平滑轨迹点。简化实现：打断后嘴部开合度序列的扰动面积，对照"无打断回放"的参考曲线做差。
2. **打断窗口音素-视位失配率**：[t_int, t_int+Δ] 内音频音素桶与视频视位桶不一致帧占比。音频侧音素序列用 wav2vec2/MMS 音素识别（CPU 可跑，torchaudio）；视频侧视位桶 = 嘴部开合度×宽度聚类（复用 R1 关键点 / 离线 mediapipe 教师标注嘴部密点）。
3. **半音节伪影率**：音频在音素中间被截断的比例（音素序列末端是否完整音素）。
4. **过渡平滑度**：打断点前后窗口的帧差/光流峰值对比正常播放的放大倍数。

**开发内容**：`scripts/interruption_eval/`（注入器 + 录制 + 离线分析器 + 报告输出 JSON/Markdown）；P-A 数据集全量跑分。

**验证门禁**：20 个样本人工盲评（1-5 分自然度）与 V-APT/失配率的 Spearman ρ ≥ 0.6；不达标则修指标口径（这正是"先验证再写论文"的意义）。

**产出 → 论文 Section 4（度量定义）+ Section 5.2（指标有效性验证）。**

### P-C 音频截断点选择器（方法 3 的音频半边）

**技术方案**（避开重对齐工具，保持轻量）
1. 打断时不在当前 PCM 采样点硬切，而是**回退到最近的能量谷**（局部能量最低点，通常为音节间隙）：已合成 chunk 尾部做 20ms 窗能量扫描，选谷点截断，谷前音频正常播放、谷后丢弃。
2. 无可用能量谷（连续浊音）时：容忍半音节截断 + 靠视频过渡帧遮盖（消融实验会证明视频过渡的贡献）。
3. 与 VAD/EOU 信号融合：EOU 已有端点先验时优先用。

**验证门禁**：P-A 数据集重放，能量谷命中率 ≥ 80%；`pytest` 回归 + 听感 smoke（录制对比样本人工抽查）。

**产出 → 论文 Section 4.3 + Section 5.3 消融（随机截断 vs 能量谷截断）。**

### P-D 过渡帧合成模块（方法 3 的视频半边，核心创新）

**技术方案（training-free，全部推理）**
1. MuseTalk 是 latent 空间口型 inpainting：打断时刻取当前帧口型区域 latent `z_now`，取 avatar 素材闭嘴中性帧 latent `z_closed`（prepare_avatar 时预提取缓存），在 VAE latent 空间插值 `z_i = (1-α_i)·z_now + α_i·z_closed`，α 从 0→1 均匀取 2–4 帧（25fps 下 80–160ms 过渡），逐帧 decode。
2. 过渡帧以 **epoch N+1 的 boundary keyframe** 身份推流（协议已支持 boundary keyframe 语义）——旧 epoch 帧失效 + 过渡帧天然衔接新语句首帧。
3. 音频淡出可选 80ms（与能量谷截断配合）。
4. 鬼影 fallback：latent 插值若出现伪影，降级像素空间 crossfade（实现留好开关）。

**验证门禁**：过渡平滑度指标比硬切改善 ≥ 50%；打断延迟全链路 p95 仍 ≤ 90ms；`pytest` 全量回归；A/B 录像抽查。

**产出 → 论文 Section 4.4（方法）+ Section 5.3（消融主证据）。**

### P-E 基线部署与主对比实验

1. LiveTalking 同机部署（独立 venv，MuseTalk 模式，WebRTC 输出），同素材、同打断脚本（统一注入器打 WebRTC 侧）。
2. 对比矩阵：**LiveTalking（硬切）/ LiveAvatar 硬切 / LiveAvatar+P-C+P-D 全量**；条件允许加"等待自然结束"上界参照。
3. 全量跑分：3 系统 × 20 打断点 × 3 素材 → V-APT / 失配率 / 半音节率 / 平滑度 / 打断延迟五指标表。

**验证门禁**：主表数据完整、每格 3 次重复取均值；显著性检验（配对 Wilcoxon）。

**产出 → 论文 Section 5.4 主实验表（核心表格）。**

### P-F 用户研究

1. 双刺激连续评分（简化 ITU ACR）：20 名被试，观看 12 组配对片段（硬切 vs 过渡，顺序随机化），评自然度/打断舒适度 1-5 分。
2. 线上问卷（自建静态页即可）+ 组间盲测；Wilcoxon 符号秩检验。

**验证门禁**：p < 0.05 且效应方向与客观指标一致；否则补样本或检讨方法。

**产出 → 论文 Section 5.5。**

## 四、风险与 Fallback

| 风险 | 影响 | Fallback |
|---|---|---|
| latent 插值出现鬼影 | P-D 方法失效 | 像素空间 crossfade（实现开关预留）；消融中如实报告两种过渡 |
| 连续语音无能量谷 | P-C 命中率不足 | 半音节截断 + 过渡帧遮盖（消融证明视频贡献占主导即可自洽） |
| LiveTalking 部署受阻 | P-E 缺外部基线 | 自实现"随机点硬切"作为内部基线 + 引用其 GitHub 工程数据定性对比 |
| 指标与人工评分相关性不足 | C2 站不住 | 调整参考曲线/窗口口径（P-B 门禁存在的意义）；必要时降级为排序一致性 (Kendall τ) |
| GPU 训练占用窗口 | P-D/E 延期 | 推理负载小，可与训练错峰短窗口跑；CPU 先行开发+单测（fake latent） |
| 用户研究样本不足 | P-F 显著性不够 | 先客观指标 + 作者盲评过渡，投稿前补足 |
