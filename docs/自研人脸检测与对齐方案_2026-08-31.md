# 自研人脸检测与对齐方案（替代 MediaPipe / YuNet）— 2026-08-31

> 对《自研组件可行性报告_2026-08-30.md》§2.4 的修订与深化。
> 原结论"模型权重无法自研 → 只能降级"经文献调研后修正为：**权重可以自研（公开数据集自训练 + 知识蒸馏），且工作量可控**。

---

## 1. 现状与功能拆解

MediaPipe / YuNet 在本项目中的全部调用面（已 grep 确认，共 2 个文件，**均为离线预处理，不在运行时链路**）：

| 组件 | 调用位置 | 提供的功能 | 产物 |
|---|---|---|---|
| OpenCV YuNet (`cv2.FaceDetectorYN`) | `scripts/prepare_avatar.py:87` | 人脸 bbox 检测（320×320 输入） | `coords.pkl`、`mask_coords.pkl`（口型区域坐标，供区域编码器） |
| MediaPipe FaceLandmarker (VIDEO/IMAGE) | `scripts/face_align.py` | 478 点人脸网格 → 取 5 点（双眼角/鼻尖/嘴角×2） | 相似变换 → 768×768 对齐视频/图像（提升 MuseTalk 唇同步质量） |

关键观察：
1. **只需 5 个点**，不需要 478 点 3D 网格——任务规模远小于 MediaPipe 全量能力；
2. 检测只需"正脸、单脸、较大"场景（用户上传的数字人素材），不需要 WIDER hard 集（10×10 小脸、密集人群）的全部鲁棒性；
3. 两者都是**离线一次性**流程，精度可用"与现结果的一致性"来验收，风险极低。

## 2. 前沿文献调研

### 2.1 微型人脸检测（对应 YuNet 替代）

| 方法 | 出处 | 规模 | WIDER val AP (E/M/H) | 要点 |
|---|---|---|---|---|
| **YuNet**（现状） | Machine Intelligence Research 2023 | ~0.1MB int8 | 0.884 / 0.866 / 0.750 | 单级 anchor，5 点联合回归 |
| **BlazeFace**（MediaPipe 自家检测器） | arXiv 1907.05047, 2019 | **0.5MB** | — | Depthwise Separable Conv + 单尺度 FPN，6 点；**结构最简，最适合自研复刻** |
| **RetinaFace-MobileNet0.25** | CVPR 2020 | 0.4M 参数 / 1.7MB | 0.885 / 0.870 / 0.806 | FPN+SSH+多任务（bbox+5点） |
| **SCRFD-500M** | ICLR 2022 | 0.6M / 2.5MB | 0.906 / 0.881 / 0.685 | 样本-算力再分配搜索轻量 backbone |
| CenterFace / YOLOv8-Face 等 | 2020/2023 | 7–12MB | 0.78–0.80 (H) | 精度高但偏大 |
| LAE-GSDetect | ICCK TSCC 2025 | 7.5 GFLOPs | 低光小脸 | 证明当前边缘检测研究已转向"低光/小脸"等极端场景——本项目**不需要**这一档复杂度 |

**结论**：YuNet / BlazeFace 这一档（0.5–2.5MB、毫秒级）是成熟且结构极简的目标，anchor 单级 + DSConv backbone 完全可以在 torch 中自写结构与训练，输入 256–320px。

### 2.2 面部关键点检测（对应 5 点对齐替代）

| 方法 | 出处 | 要点 |
|---|---|---|
| **PIPNet** | IJCV 2023 | heatmap+偏移联合、**无后处理、单步解码**，为效率而生——自研学生的首选范式 |
| **POPoS** | arXiv 2410.09583, 2024 | 伪距多边定位修正 heatmap 量化误差，低分辨率下优势大 |
| **D-ViT / 级联双视觉 Transformer** | arXiv 2411.07167, 2024 | WFLW/300W/COFW SOTA，但为精度向，体量大，不适合学生模型 |
| **Proto-Former** | arXiv 2510.15338, 2025 | 统一多数据集关键点原型 Transformer，思路可借鉴（多数据集统一标注），实现过重 |
| 3DDFA_V2 | ECCV 2020 | 3D 稠密对齐，>我们的需求 |
| PFPLD | ncnn 生态 | 98 点嵌入式方案，证明 100 点级模型可 <1MB |

**结论**：5 点回归用 PIPNet 式 "tiny heatmap+offset" 学生网络即可，参数量 0.3–1M 档有充分先例（SD-HRNet 蒸馏到 0.98M 仍保持 SOTA 级）。

### 2.3 知识蒸馏 / 伪标签（让"权重自研"质量达标的关键）

- **KD-Loss**（ACM TOG 2021, aliprf/KD-Loss）：双教师（Tolerant/Tough）蒸馏轻量学生做关键点，证明 1M 级学生可逼近大教师。
- **SD-HRNet**（Sensors 2023）：剪枝 + 三重蒸馏，0.98M–1.32M 参数达到 300W/WFLW 竞争精度。
- **回归+heatmap 联合优化 + 外部蒸馏监督**（Applied Sciences 2024, 10.3390/app14167153）：遮挡/大角度下显著更稳。
- **Noisy Student 式伪标签自训练**（Xie et al. 2020）：允许用 MediaPipe（仅训练期）对无标注素材打伪标签——**训练后即可卸载 MediaPipe**。

### 2.4 数据集与许可

| 数据集 | 标注 | 许可 | 用途 |
|---|---|---|---|
| WIDER FACE | bbox（E/M/H） | 仅限非商业研究 | 检测器主训练集 |
| 300W / 300VW | 68 点（图像/视频） | 研究许可 | 关键点真值（68→5 点映射：眼角 36/45、鼻 30、嘴角 48/54） |

## 3. 自研边界界定（与既定约束对齐）

延续"运行时仅 numpy + torch + 标准库"的自研标准：

- **自研**：网络结构定义、训练管线（损失/增强/优化）、推理前处理与 NMS 后处理、权重（公开数据 + 伪标签自训练产物）；
- **训练期专用、训练后卸载**：MediaPipe（478 点教师伪标注）、cv2 YuNet（bbox 预标注辅助）。它们退化为一次性标注工具，不再出现在 `pyproject.toml` 运行依赖中；
- **保留**：torch（已是运行依赖）、opencv（图像 IO/仿射变换等基础算子，属既定保留项）。

## 4. 推荐方案 R1：自研双模型 + 蒸馏管线

```
训练期（一次性，GPU）                      运行期（自研，CPU/GPU）
┌─────────────────────────────┐          ┌──────────────────────────┐
│ WIDER FACE ── bbox 真值 ──┐ │          │ prepare_avatar.py        │
│ 300W/300VW ─ 68点真值 ──┐ │ │          │  └─ FaceDetectorSelf     │
│ 自有素材 ── MediaPipe教师┐│ │ │   权重   │      └─ bbox + 口型坐标  │
│  （478→5点伪标签）──────┤│ │ │  ═════>  │  └─ LandmarkNet5Self     │
│                         ▼▼▼▼ │          │      └─ 5点 → 相似变换   │
│  M1 检测学生 + M2 关键点学生 │          │  （cv2 仅做 warp/imio）  │
└─────────────────────────────┘          └──────────────────────────┘
```

### M0 数据与标注管线（离线脚本 `scripts/make_face_dataset.py`）
- WIDER FACE train 子集 → 检测样本（bbox 真值）；
- 300W/300VW → 5 点样本（标准 68→5 映射）；
- 自有素材逐帧 → MediaPipe 教师（478 点→5 点 + bbox 伪标签，含置信度过滤）；
- 产出统一 `data/face_ds/{images,labels}` + `manifest.json`（含来源/真值or伪标签标记）。

### M1 自研检测器 `FaceDetectorSelf`（目标对标 YuNet@320）
- 结构自写：DSConv backbone（≈BlazeFace-lite）+ 2 尺度 FPN 头 + 单级 anchor；
- 损失：focal（分类）+ smooth-L1（bbox）；NMS 用 numpy 向量化自写；
- 产物：`weights/self/facedet_320.pt`，目标 **<1MB**；
- 精度门禁：WIDER val AP_easy ≥ 0.85（YuNet=0.884），自有素材召回 100%。

### M2 自研关键点学生 `LandmarkNet5Self`（对标 MediaPipe 5 点）
- 结构自写：PIPNet 式 tiny heatmap(5 通道)+offset 头，backbone ≈0.5M 参数；
- 损失：heatmap MSE + offset L1 + 坐标蒸馏（教师 5 点软标签）；
- 门禁：300W 测试子集 5 点 NME ≤ 3.0%；自有素材与 MediaPipe 教师平均点距 ≤ 1.5px（对齐 256 裁剪）。

### M3 集成与双后端开关
- `FACE_BACKEND=yunet|self`、`LANDMARK_BACKEND=mediapipe|self`（默认先 self，沿用 transport 的过渡惯例：旧后端保留 2 个 minor 版本）；
- `face_align.py` 重构为后端工厂；`prepare_avatar.py` 检测步骤同构切换；`download_models.py` 改为拉取自研权重（权重文件随 repo/HF 托管）。

### M4 下游一致性验收（真正的验收标准）
| 指标 | 门禁 |
|---|---|
| 对齐输出一致性 | 自研 vs MediaPipe 对齐后 768 图像：眼/嘴区域平均像素偏差 ≤ 2px，SSIM ≥ 0.97 |
| 口型 mask 一致性 | `mask_coords.pkl` IoU ≥ 0.95（区域编码器下游不受影响） |
| MuseTalk 端到端 | yongen 重跑，唇同步盲评不降级 + latents 余弦相似度 ≥ 0.99 |
| 速度 | CPU 单帧（检测+5点）≤ YuNet+MediaPipe 现耗时 ×1.5 |
| 测试 | 新增单测（几何/NMS/训练循环小样）+ 上述一致性集成测试，CI 全绿 |

### 第二轮 GPU 迭代实测（2026-09-02，全部为**负结果**，v1 仍最优）

按上表对策 ①②③ 执行，全部对照实验在 `镜域mirror/.venv`（torch 2.7.0+cu128）完成，变量逐一分离：

| 变体 | epochs | 增强 | 解码 | 裁剪框 | eye/mouth dev | SSIM | mask IoU |
|---|---|---|---|---|---|---|---|
| v1（首轮基线） | 240 | 无 | argmax | facedet_256 | **0.94px** | 0.65 | 0.896 |
| v2 | 150 | 有 | soft（DSNT 归一化期望） | facedet_320 | 37px | — | — |
| v3 | 200 | 有 | argmax | facedet_320 | 4.59px | 0.60 | 0.694 |
| v4 | 200 | 有 | argmax | facedet_256 | 3.21px | 0.65 | 0.896 |
| v5 | 200 | 无 | argmax | facedet_256 | 2.23px | 0.63 | 0.896 |

**实测结论（证据驱动，均已验证根因）**
1. **soft/DSNT 解码在真实热图上不可用**：`sigmoid→归一化→期望坐标` 被背景 sigmoid 质量主导（48×48 网格背景质量 ≫ 峰值），期望坐标被拉向网格中心，逐帧误差恒定 ~37px（逐帧诊断：soft 37.2px vs argmax 3.5px）。纯 softmax(logits·β) 同理受 logit 幅度影响退化为近似 one-hot。**argmax+offset 仍是正确选择**；代码保留 `decode_mode` 通路（ckpt 内记录，默认 argmax），soft 仅作实验存档。
2. **翻转/亮度增强有害**：同配置 200ep，有增强 3.21px vs 无增强 2.23px。微型关键点网络（<0.5M 参数）对热图峰形敏感，增强噪声减慢峰形收敛。
3. **长训练过拟合**：240ep(v1, 0.94px) → 200ep 重训反而 2.23px。注意 v1 的 240ep 是在 width 48 下训练的；本轮 v4/v5 沿用 width 32，epoch 增多对小宽度模型是过拟合。**不再重训 M2，v1 权重保持最优**。
4. **M1-320 增训失败**：80ep + 翻转增强后检测框**系统性偏大且左移**（对 YuNet IoU 从 0.86 掉到 0.58，逐帧 x1 约 -30px / y2 约 +25px），并连带劣化继承其框的 M2（mask IoU 0.896→0.694）。`facedet_320.pt` 归档不用；M1 疑点（320 输入下 anchor 回归偏置 / 翻转增强）留待下轮单独排查。

**修订后的对策（替代上表）**
- mask IoU 门限：**采用"mask 坐标改由关键点派生"**（原表备选项）——两个后端各自从 5 点派生口型区域，语义对齐后不再依赖检测框一致性（v1 逐点 0.94px 支撑该路径可达 0.95 门限）。
- SSIM 门限：按"同点集验实现确定性"口径重新评估（原对策④），点差异由 dev 门限体现。
- argmax 跳变：测试时 3×3 平均池化（原对策）仍待实施。
- 数据/解码方向（①②）经实测排除；width 48 + 240ep 的 v1 配置即为当前最优配方。

### 关键点派生 mask 实测（2026-09-02，CPU）

**实现**（已落地，测试全绿）：
- `FaceBox.points5`：YuNet 自带 5 点回归直接落框；self 后端经 M2 网络获取。
- `face_align.mask_box_from_points5`：眼中点/嘴中点定中心，眼间距 d 定尺度（半宽 1.35d / 半高 1.30d，与传统 det-box+25% padding 比例对齐）。
- `prepare_avatar._detect_faces`：优先 points5 派生 mask 坐标，关键点缺失时回退 padded-box。
- `accept_face_backend`：mask IoU 改为双方关键点派生框的 IoU，不再传入检测框。

**实测数字**（out.mp4，8 帧，legacy=mediapipe vs self=v1 landmarks5_192）：

| 指标 | det-box 口径（旧） | 关键点派生口径（新） |
|---|---|---|
| mask IoU（逐帧均值） | 0.896 | **0.926** |
| 逐帧 IoU 范围 | — | 0.890–0.964 |
| eye/mouth dev | 0.94px | 0.94px（不变） |
| union 区域 IoU | — | 0.901（transport region.json 口径） |

**结论：门限 0.95 仍未过，根因是关键点精度本身而非派生公式**：
1. 原始帧仅 ~400px、眼距 d≈110px，两后端逐点偏差 0.2–8.0px（0.2–7% 相对眼距），眼间距比值 d_ratio 均值 1.017 / std 0.038——每次 ±4–6% 的尺度波动直接进入 box 宽高（±5.7px 半宽差 / ~300px box），IoU 上限即 ~0.96。
2. **对齐帧上重回归口径被否决**：warp 后的合成图（768px、眼距 245px）超出两个回归器训练分布，分歧 13–30px，box 退化成整帧，产生假 1.0；下采样到 256（眼距 82px）仍 4–9px 分歧。**验收必须在原始帧坐标系进行**（已写死在 harness docstring）。
3. 眼嘴距替代眼间距作尺度源无收益（vm_ratio std 0.042 ≥ d_ratio std 0.038）——偏差是逐帧随机的，非系统性。

**下一步方向**（二选一或并行）：
- 提升 M2 精度：argmax 前 3×3 平均池化（待办）+ 用更高分辨率素材重跑验收（d 越大相对误差越小）；
- 若精度无法达标，重评 mask IoU 门限语义：0.926 已消除检测框差异（旧口径 0.896 的主因），剩余差距反映的是可接受的关键点抖动，可论证门限从 0.95 放宽至 0.90（配 union 口径复核）。

### 第三轮：3×3 池化 + 高分辨率素材实测（2026-09-02，CPU）

**实现**（已落地，全量 645 测试 + ruff 绿）：
- `LandmarkNet5Self.decode_landmarks(..., pool=True)`：argmax 前 3×3 平均池化（stride 1），压平近邻等值峰间的单格跳变；offset 仍在（可能重选的）argmax 格收取。
- `pool_before_argmax` 模型属性：ckpt 可存（`train_face_landmarks.py --pool`），推理可用 `LANDMARK_POOL=1/0` 环境变量覆盖（`load_lm_model`）。v1 ckpt 未动，验收用 `LANDMARK_POOL=1`。

**300W 上的重大发现（负结果，但重要）**：self 后端在 300W 高清大图（1004×753）上整体分布外失效——M1 检测器 200 张漏检 146 张、检出的框系统性偏移（indoor_001: 框 (492,58,735,293) vs GT (461,89,183²)，IoU≈0.5）；landmark 网在 GT 点紧框 crop 上预测失控（标准 inter-ocular NME 中位数 ≈44%，plain 与 pooled 同样失控，与池化无关）。**v1 的 dev 0.94px 只在其训练分布（低分辨率视频帧）内成立**，不能以 300W 作为 self 后端验收素材。

**out.mp4 实测矩阵**（8 帧，mask IoU = 关键点派生框 vs mediapipe）：

| 素材 / 解码 | mask IoU | 帧间抖动(相对) | dev(px) |
|---|---|---|---|
| 原始 400px + plain | 0.9258 | 15.9 | 0.94 |
| 原始 400px + pooled | 0.9420（fail） | **11.0（-31%）** | **0.85** |
| 2×Lanczos + plain | **0.9536（pass）** | 31.2 | — |
| 2×Lanczos + pooled | **0.9537（pass）** | 22.1 | 1.05 |

**结论**：
1. **池化有效且无害**：原始素材 IoU +1.6pp、帧间抖动 -31%、dev 0.94→0.85px；2× 素材下与 plain 等效（分辨率已消除量化噪声）。建议生产默认开启（下次重训时 `--pool` 固化进 ckpt，或设置 `LANDMARK_POOL=1`）。
2. **分辨率假设成立**：2× 放大即过 0.95 门限（0.9537）。网络输入是固定 128/192 的脸 crop，更大源图 → crop 下采样链路更平滑、亚像素信息更多，mediapipe 侧同样受益。原生 ≥720p 素材预期更好。
3. **mask IoU 门限在 2× 素材 + 池化口径下 PASS**（报告 docs/m4_accept_report_points5_pool_2x.json）；SSIM 仍 fail（0.69，待"同点集确定性"口径重评）。
4. 待办新增：M1 检测器泛化（高清大图漏检/框偏移）是 self 后端走向真实高清素材的下一块短板；300W 可作为 M1 重训/增训数据源（round-2 的 320px 增训失败是"视频帧增训"，高清静态图分布还没进过训练集）。

### M1 泛化增训实测（2026-09-02，GPU）——不达标，不切换

**训练**：全 manifest（w300 高清框首次入训），40ep / 256 / width 48，final loss 0.5986。产物 `weights/self/facedet_256_v2.pt`。

**验收**（300W 子集 200 张，conf 0.5）：

| 指标 | 门限 | v1 | **v2** |
|---|---|---|---|
| 300W recall | ≥90% | 27.0% | **36.0%** ✗ |
| 检出框 IoU vs GT | ≥0.7（mean） | 0.310 | **0.251** ✗（回退） |
| out.mp4 mask IoU（v2det+v2lm） | ≥0.9555 | 0.9555 | 0.9584 ✓ |

**判定：增训失败，facedet_256_v2 归档不用，默认保持 v1。**

**根因**：w300 仅 600/13676 条（4.4%）欠采样，且其 GT 点派生紧框（无额头）与 WIDER 人标框（含全脸）标注风格冲突——混合训练后模型对高清大脸分布依旧学不会，框还变得更散。

**下一步候选**（需重新设计数据策略，非简单加 epoch）：
1. **过采样重训**：w300 条目复制 ×8-10 并改用 mediapipe 检测框（人标风格，与推理一致）替代 GT 紧框；
2. **分辨率均衡**：WIDER 原图 resize 到 ~640px 侧入训，避免 256 归一化后 300W 大脸在小网格 anchor 上的尺度失配（TinyFaceDetector 单尺度 anchor 对极端大脸可能天然不适配，需检查 anchor 尺度范围 vs 300W 脸占比）；
3. **务实绕行**：self 后端在高清素材场景外挂 YuNet det（YuNet 是 legacy 组件，不满足"全自研"但可作为可选 fallback 路径），self landmark 网在 YuNet 框上重新校准（M2 联动重训）。
**附带修复**：`face_self.detect()` docstring 声称返回 xyxy_norm，实际一直是像素 xyxy（调用方均按像素消费）——已更正文档，无逻辑变化。60 项 face 测试 + ruff 绿。

### Anchor 尺度适配检查（2026-09-02，CPU 诊断）

对 manifest 全部 160k 框做"同中心 IoU 上限 vs 3 个方形 anchor (0.15/0.30/0.50)"覆盖率分析（0.5-IoU 匹配下拿不到正样本 = 训练时被 `detection_loss` 直接忽略）：

| 数据源 | 框数 | 尺寸 max(w,h) 中位 | 纵横比 h/w 中位 | 无监督框占比 |
|---|---|---|---|---|
| wider | 159,393 | 0.028 | 1.82 | **96.1%** |
| w300 | 600 | 0.195 | 1.37 | 35.5% |
| own (out.mp4) | 200 | 0.303（方形） | 1.00 | 0% |

**结论**：
1. **不是缺大 anchor**：+0.75 anchor 对 w300 无改善（35.5%→35.3%）；失配主力是中等尺寸 + 纵横比 1.4-1.8 的框与方形 anchor 的形状谷。
2. **重磅现状：WIDER 96.1% 的框从未产生过正样本监督**（脸中位仅 2.8% 边长，0.5-IoU 对 0.15 最小 anchor 全军覆没）。v1 实际有效监督 = WIDER ~6.2k 框 + own 200（唯一 100% 匹配源，即 out.mp4 方形脸）+ w300 64.5%——检测器实为"方形大脸检测器"，这直接解释了 300W/高清泛化失败。
3. w300 35.5% 无监督与 v2 recall 36% 的数字耦合：学会的上限本身就低。

**修复收益量化**（无监督占比）：

| 方案 | wider | w300 |
|---|---|---|
| 现状 3 anchors @0.5 | 96.1% | 35.5% |
| 3 anchors @0.4 | 93.9% | 29.5% |
| 3 anchors + 强制最佳匹配（SSD 式保底） | 0% | 0% |
| 5 anchors (0.05,0.10,0.15,0.30,0.50) @0.5 | 81.0% | **3.0%** |
| 5 anchors + 强制最佳匹配 | 0% | 0% |

**建议**：方案 B——`NUM_ANCHORS` 3→5（0.05/0.10/0.15/0.30/0.50，head conv 通道数随之变化，ckpt 结构不兼容需重训）+ 强制最佳匹配（`detection_loss` 每 GT 保底一个正样本 anchor）+ w300 过采样 ×8 与 mediapipe 风格框（候选①）组合。注意 WIDER 小脸即使强制匹配，回归目标仍然激进（dw≈log(0.028/0.05)≈-0.58 起），focal 分类与 box 回归都要靠 5-anchor 拉近距离。

### M1 v3/v3b/v3c 实测（2026-09-02，GPU）——泛化达标、域内联动未闭环，默认保持 v1+v2

**实施**：按方案 B 全部落地——`NUM_ANCHORS=5` + `detection_loss` 强制最佳匹配 + `make_manifest_det.py`（w300 YuNet 框替换 + ×8 过采样，manifest_det.jsonl 17876 行）+ ckpt 记录 `anchor_sizes`（`load_det_model` 动态适配，legacy 3-anchor ckpt 兼容加载）+ `train_face_det.py --init` 热启动续训。RTX 5080（镜域mirror venv cu128）。

| 产物 | 训练 | final val loss |
|---|---|---|
| facedet_256_v3.pt | manifest_det 40ep/256/48/lr1e-3 | 0.7000 |
| facedet_256_v3b.pt | v3 热启动 +40ep/lr5e-4 | 0.6694 |
| landmarks5_192_v3b.pt | M2 重训（v3b det 框 crop，conf 0.5） | 0.3852 |
| landmarks5_192_v3c.pt | M2 重训（v3b det 框 crop，conf 0.3，减少 GT 回退） | 0.4021 |

**M1 检测评估（300W 子集 200 张）**：

| 口径 | v1 | v2 | v3 | v3b |
|---|---|---|---|---|
| 旧口径 recall@0.5 vs GT 紧框（conf 0.5） | 17.0% | 19.5% | 24.0% | 26.5% |
| **新口径 self-recall vs YuNet 参考框 @conf 0.3** | — | — | 89.0% | **93.5%** |
| 新口径 @conf 0.35 | — | — | — | 91.5% |

**重大口径发现：旧门限结构性不可达。** "300W recall ≥90% vs GT 紧框"对 YuNet 风格检测器在数学上不可能——把 manifest_det 的 YuNet 参考框当"完美预测"算上限：YuNet 框 vs GT 紧框 IoU mean 0.325 / median 0.443，**ceiling recall@0.5 = 40.5%**。v1 的 27% 其实已到上限的 2/3。旧门限是给 GT 紧框风格的 v2 定的；v3 线按设计学 YuNet 风格（与推理/下游 crop 消费一致），评估参考必须换成 YuNet 框。w300 部分多脸图只保留最大脸也计入 miss。

**out.mp4 域内联动（切换门，8 帧顺序帧）**：

| 组合 | dev px（≤2） | mask IoU（≥0.95） | d_ratio（眼距比 mean±std） |
|---|---|---|---|
| v1det+v2lm（基线） | 0.719 ✓ | **0.9555** ✓ | 1.0199±0.0164 |
| v3bdet+v2lm | 2.158 ✗ | 0.9568 ✓ | 0.9911±0.0198 |
| v3bdet+v3blm | 1.216 ✓ | 0.9285 ✗ | 1.0127±**0.0380** |
| v3bdet+v3clm | 1.070 ✓ | 0.9369 ✗ | 1.0103±**0.0347** |

**根因分解**：mask IoU 对眼距 d 的帧间稳定性敏感（mask 框 scale=眼距）。v3blm/v3clm 的 d_ratio 方差 0.035-0.038（基线 0.016）直接吃掉 2pp IoU。det 框本身偏移很小（frame 28 实测 dx-0.003/dy+0.021/dw-0.018/dh-0.010）。v3 系关键点网在 out.mp4 域的尺度稳定性有内在劣势，det_conf 0.3 重训（减少 w300 GT 回退 crop）只回收了一半。

**out.mp4 det sanity**：v3b 每帧恰 1 检出、无噪声、score 0.75-0.81、与 YuNet IoU 0.66-0.74（v1≈0.86，略退化）。

**判定**：M1 泛化目标达成（新口径 ≥90% @conf 0.35），但域内 mask IoU 未闭环（0.9369 < 0.9555 基线）。**默认保持 v1det+v2lm 不切换**；facedet_256_v3b / landmarks5_192_v3c 归档为高清/泛化可选线。遗留决策：① 域内门限重谈（0.95→0.90 则 v3c 可切，换 300W 泛化）② own 素材扩采 + own 过采样 M2 重训 ③ self 后端运行时 det_conf 默认值（v3b 在高清静态图上需要 0.3-0.35，视频域 0.5 无影响）。

**决策落定（2026-09-02，用户确认）**：
- ① ② → **维持现状**：默认保持 v1det+v2lm；v3b/v3c 归档为可选线，门限不重谈；own 扩采暂不做。
- ③ → **self 后端 det_conf 默认降为 0.35**：`face_backend` 新增 `resolve_det_conf`（None → self 0.35 / yunet 0.5），`detect_faces`/`landmarks5` 的 conf 参数改为 `float | None`，显式传参不受影响（prepare_avatar 仍显式 0.7）。测试 ResolveDetConfTests ×2；全量 pytest + ruff 绿。

**测试**：全量 pytest 绿（exit 0）+ ruff 绿（face_self E501、test_face_backend fake ckpt 补 anchor_sizes）。报告：docs/m4_accept_report_v3b.json / _v3b_m2.json / _v3c.json。

## 5. 备选路线对比

| 路线 | 内容 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **R1（推荐）** | 全自研：结构自写 + 公开数据自训练 + 教师蒸馏 | 真正自研；运行依赖只剩 numpy+torch+cv2；权重可控可分发 | 工作量最大；训练期需短暂使用 MediaPipe | ✅ 采纳 |

## 6. 风险与对策

| 风险 | 对策 |
