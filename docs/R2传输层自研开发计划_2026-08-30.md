> 日期：2026-08-30　|　前置：[自研组件可行性报告](file:///e:/项目/LiveAvatar/docs/自研组件可行性报告_2026-08-30.md) §2.3
> 目标：移除 LiveKit Server / `livekit` Python SDK / `livekit-client` JS 三个外部系统，改为**自研 WebSocket 视频传输协议 + 浏览器自研播放器**
> 硬约束：主体功能完整 —— 实时口型视频、毫秒级打断（epoch）、多会话、降级链、API-Key 鉴权，全链路测试/CI 全绿
> 预估总量：**26–30 人日**，6 个里程碑（M0–M6），每里程碑带测试与 DoD

## 1. 目标与非目标

**目标（In scope）**
1. 新增自研二进制视频协议（服务端帧打包 + 浏览器解包合成）；
2. 新增 `WebSocketSink`（实现现有 `PublishSink` 协议，见 [sinks.py](file:///e:/项目/LiveAvatar/src/liveavatar/sinks.py#L22-L40)）与 `/v1/sessions/{sid}/video` WS 端点；
3. 浏览器端自研播放器（抖动缓冲 + 时钟同步 + canvas 合成），替换 [app.js](file:///e:/项目/LiveAvatar/web/app.js) 中的 livekit-client；
4. 自研**域感知区域增量编码**（利用数字人"只有口型区域在动"的先验，带宽 ↓ ~80%）；
5. 自适应质量与弱网对抗（简化版拥塞控制）；
6. 传输层特性开关（`livekit` 保留一个过渡期，默认切换为自研）。

**非目标（Out of scope）**
- 不复刻 WebRTC/SFU 协议栈（ICE/DTLS/SRTP）；
- 不实现 H.264/AV1 编码器（避免引入新的编码器开源工程；WebCodecs 硬解作为可选扩展位）；
- 不做跨公网 P2P/NAT 穿透（v1 面向单服务器直连场景）。

## 2. 前沿参考与借鉴点

| # | 参考 | 类型 | 借鉴什么 |
|---|---|---|---|
| 1 | **IETF MoQ（Media over QUIC）**, draft-ietf-moq-transport | 标准草案 | "低延迟媒体传输 = 单向推流 + 独立可解码对象 + 订阅者反馈"的整体形态；我们的 WS 协议是其 TCP 简化版 |
| 2 | **RFC 8298（GCC，Google 拥塞控制）** | RFC | 基于延迟梯度/队列深度的带宽估计思想 → 简化为 EWMA RTT + 队列深度双信号 |
| 3 | **Ramjee et al., "Adaptive Playout Mechanisms for Packetized Audio" (INFOCOM'94)** | 论文 | 自适应抖动缓冲经典算法：基于到达间隔方差的播放期限调整，本项目移植到视频帧 |
| 4 | **RFC 3550（RTP/RTCP）** | RFC | PTS 时钟模型、发送/接收时钟漂移校正（RTCP SR 的 NTP↔RTP 映射思想） |
| 5 | **W3C WebCodecs / MSE / WebTransport** | 规范 | WebCodecs 作为未来硬解扩展位；WebTransport(QUIC) 作为 v2 传输演进路线 |
| 6 | **QUIC RFC 9000/9002** | RFC | 丢帧 vs 重传的取舍：实时媒体"宁丢不等"——指导我们放弃 TCP 内重传等待的对抗策略 |
| 7 | **Wav2Lip (Prajwal et al., ACM MM 2020)** | 论文 | 口型只改变面部小区域的先验 → 区域编码的理论依据（本项目 mask/coords 数据现成） |
| 8 | **SRT (Haivision) / LL-HLS** | 协议 | ARQ 与延迟的权衡基线；确认"帧独立 + 主动丢弃"优于"重传等待" |

**本计划最核心的原创设计（D2/D3）**：数字人每帧 = 静态底图 + 口型区域更新。据此设计**区域独立帧编码**（intra-only region codec）——每个 P 帧只携带口型区域的 JPEG 替换块（非残差），**任意帧可独立解码、可任意丢弃**。这与 epoch 打断"丢过期帧"的语义天然吻合：丢帧永远安全，不需要参考链、不需要重传。

## 3. 关键技术决策

### D1 传输通道：WebSocket（TCP）v1，WebTransport(QUIC) v2 演进

| 方案 | 延迟 | 实现成本 | 弱网 | 结论 |
|---|---|---|---|---|
| WebSocket (TCP) | 中（HoL 受限） | 低 ✅ | 中 | **v1 选定**：帧独立设计抵消 HoL——拥塞时丢帧不重传 |
| WebTransport (QUIC) | 低 | 中（需 aioquic） | 好 | v2 演进，协议层预留 |
| WebRTC DataChannel | 低 | 高（回到协议栈复刻） | 好 | 明确不做 |

### D2/D3 编码：MJPEG 基线 + 自研区域独立帧（双档）

| 编码 | 单帧大小 | 带宽@25fps | 适用 |
|---|---|---|---|
| 原始 I420 512² | 393 KB | ~78 Mbps | 仅本地 |
| **MJPEG 全帧 q80**（基线） | ~35 KB | ~7 Mbps | 局域网 / v1 前期 |
| **区域独立帧**（自研，目标档） | 1×全帧/s + 24×口型块(~5KB) | **~1.5 Mbps** | 公网 / 最终形态 |

区域块编码以 avatar 预处理的 mask/coords 为依据（数据已存在 `data/avatars/*/mask/`）；`prepare_avatar` 增加产出"口型区域包围盒"。

### D4 时钟：服务端 PTS 主时钟 + 客户端自适应抖动缓冲

- 服务端沿用 pipeline 的 PTS 单调时钟（音频时长驱动，"TTS 是主时钟"原则的延续）；
- 客户端播放期限 = `t_arrival + target_delay`，`target_delay` 按到达间隔 EWMA 方差自适应（Ramjee 算法移植），基准 2 帧（80ms），上限 10 帧；
- PTS↔本地时钟漂移用最小二乘斜率校正（RFC 3550 SR 思想的单端简化）。
- **打断特殊路径**：epoch 变更帧到达时**立即清空抖动缓冲**——打断延迟不受缓冲深度影响（硬指标 ≤1 帧）。

### D5 背压：有界队列 + drop-oldest，永不阻塞推理

`WebSocketSink` 内部 `asyncio.Queue(maxsize=8)`；`publish_frame` 满则丢最旧帧并计数（帧独立可任意丢）。发送协程独立消费，与推理解耦。

### D6 自适应：服务端队列深度 + 客户端 EWMA 反馈（简化 GCC）

- 服务端信号：发送队列水位 > 50% 持续 1s → JPEG 质量 90→75→60→45 分档降级；水位回落回升；
- 客户端信号：每 500ms 回报 `{rtt_ms, received, dropped}`（ping/pong 测 RTT）；
- 两信号取交集决定当前质量档；关键帧请求（重连/epoch）优先级最高。

### 延迟预算（局域网目标 ≤150ms，公网 ≤400ms）

| 环节 | 预算 |
|---|---|
| 推理产出 → sink 入队 | ≤5ms |
| JPEG/区域块编码（cv2，512²） | 2–5ms |
| 发送队列 | ≤1 帧（40ms） |
| 网络传输（LAN） | 1–5ms |
| 客户端抖动缓冲 | 80ms（自适应 80–400ms） |
| 解码 + canvas 合成 + 渲染 | 5–15ms |
| **合计** | **~135–150ms（LAN）** |

## 4. 总体架构

```text
推理侧（不变）
  AvatarWorker → AvatarStreamingAdapter → PublishSink 协议
                                             │
              ┌──────────────────────────────┼──────────────────────────┐
              │ WebSocketSink（新，默认）      │ AvatarVideoPublisher（过渡）│ RtmpSink（已有）
              │  有界队列 + drop-oldest       │  LiveKit track            │
              │  帧编码器: MJPEG / 区域帧     │                           │
              └──────────────┬───────────────┴──────────────────────────┘
                             ▼
        GET/WS  /v1/sessions/{sid}/video   ←—— 新端点（二进制视频下行 + JSON 控制上行）
                             ▼
        浏览器 Player（新，web/player.js）
          WS 收包 → 解包 → epoch/seq 过滤 → 自适应抖动缓冲
          → canvas 合成（底图 bitmap + 口型块 drawImage）
          → 打断: epoch 帧清空缓冲
          → 反馈: 每 500ms 上行 {rtt, received, dropped} / keyframe_request
```

## 5. 传输协议规范（冻结后写入 `docs/PROTOCOL.md`）

### 5.1 二进制视频帧（服务端 → 客户端，小端）

```text
偏移  类型      字段
0     u8        msg_type        1 = video_frame
1     u8        flags           bit0 keyframe / bit1 epoch_boundary / bit2 eof_stream
2     u8        codec           0 = mjpeg_full, 1 = region_delta
3     u8        quality         本次 JPEG 编码质量 (1–100)
4     u16       seq             帧序号 (回绕)
6     u32       epoch
10    i64       pts_us          服务端 PTS（微秒）
18    u16       width
20    u16       height
22    u32       payload_len
26    ...       payload
```

**payload（codec=1 区域帧）**：`u16 patch_count` 后跟 patch 数组，每项：
`u16 x | u16 y | u16 w | u16 h | u32 jpg_len | JPEG 字节`
（坐标为块左上角；w/h 为偶数对齐；块独立可解码，非残差）

**payload（codec=0 全帧）**：单个 JPEG。

### 5.2 JSON 控制消息（双向）

```jsonc
// 客户端 → 服务端
{"type":"hello","caps":{"codec":["region_delta","mjpeg_full"],"max_fps":25}}
{"type":"feedback","rtt_ms":12.3,"received":120,"dropped":2}   // 每 500ms
{"type":"keyframe_request"}
// 服务端 → 客户端
{"type":"ready","codec":"region_delta","target_fps":25,"width":512,"height":512}
```

### 5.3 会话语义

- 视频帧统一携带当前 epoch；`cancel_epoch` 后 sink 侧先丢过期帧（与 `AvatarVideoPublisher` 一致），并在下一帧打 `epoch_boundary` 标记（= 关键帧）；
- 客户端重连/hello 后必须收到 keyframe 才开始合成；
- 会话删除 → 服务端发 `eof_stream` 并关闭 WS。

1. 会话创建 → 浏览器实时观看 25fps，LAN 延迟 P95 ≤ 200ms；

4. 3 并发会话 × 10 分钟无串帧、内存平稳；
5. 弱网（200ms/5% 丢包）降画质不冻结，恢复 2s 回满；
6. 降级链（MuseTalk → Static → 音频独播）在 ws 模式下行为不变；
7. 全量测试 / ruff / mypy / coverage ≥80% / CI 全绿；
8. 带宽 ≤ 2 Mbps（区域帧档），对比报告归档 `docs/`。

## 9. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| TCP HoL 在公网造成卡顿 | 中 | 帧独立可丢（D3）+ drop-oldest + 自适应降质；必要时 v2 升 WebTransport（协议已预留 codec/flags 字段） |
| 浏览器 canvas 合成性能 | 低 | 底图用 ImageBitmap 缓存，仅重绘口型块（<64×64 区域 blit，CPU 占用可忽略） |
| 口型块边缘可见接缝 | 低 | mask 包围盒外扩 8px + 4px 线性羽化（blending.py 已有类似逻辑可复用） |
| uvicorn WS 单连接吞吐 | 低 | 单会话 ~0.2–1 MB/s，远低于 WS 实测上限；多会话压测在 M3 验证 |
| 移除 LiveKit 后回退需求 | 低 | `LIVEAVATAR_TRANSPORT=livekit` 过渡开关，两个小版本后才删除代码 |
