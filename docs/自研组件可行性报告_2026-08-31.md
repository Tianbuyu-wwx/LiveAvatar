# LiveAvatar 开源依赖自研替代可行性报告（v3 全量重扫版）

> 日期：2026-08-31　|　本报告**替换**《自研组件可行性报告_2026-08-30.md》（v2）
> 触发原因：项目扩展了组件（新增 GPT-SoVITS TTS 引擎、voice/ 语音池、audio_in 音频输入链），本轮做**全量重扫**，范围从"项目级上游工程"扩大为 **Tier-1 上游工程 + Tier-2 底层库** 两层。
> 硬性约束：**替换后主体功能必须完整可用** —— 文本/音频进 → TTS 语音 + 口型视频出 → 浏览器实时观看，含毫秒级打断（epoch）、VoicePool 会话隔离、降级链。
> 评级：✅ 可行　⚠️ 有条件可行（高成本/降级/低收益）　❌ 不可行（必须保留）

## 一、结论先行

全量重扫后，项目对外部开源的绑定共 **16 项**（Tier-1 上游工程 7 项 + Tier-2 底层库 9 项）。核心结论：

1. **最大新增绑定是 GPT-SoVITS（TTS 引擎）**。绑定面三层拆解：
   - **引擎代码**：vendored 在 `third_party/GPT_SoVITS/`（MIT 许可，已提交），项目通过唯一窄接口 `GPT_SoVITS.TTS_infer_pack.TTS.TTS / TTS_Config` 调用，外层 `NvcWorker` / `VoicePool` / `NvcStreamingTtsAdapter` 全是自研封装 → 代码层**可收编为自有模块**（⚠️）；
   - **预训练基础权重**：~1.4GB（chinese-hubert-base / chinese-roberta-wwm-ext-large / s1v3.ckpt / v2Pro / eres2netv2 / fasttext lid.176.bin），**无法"写"出来，只能训练**（❌ 训练墙）；
   - **角色权重**（每角色 GPT .ckpt + SoVITS .pth + 参考音频）：本来就是自训/自采资产，**不算绑定**。
2. **新发现一个 P0 仓库缺陷**：`.gitignore:9` 的 `models/` 通配规则把**自研源码** `src/liveavatar/musetalk/models/`（vae.py、unet.py）也忽略了 —— `git ls-files` 实测该目录下**零文件被提交**，新 clone 必然 `from .models.vae import VAE` 导入失败。与自研替换无关但必须先修。
3. **Tier-2 底层库呈"两极"**：numpy / torch 是主体功能基石（❌ 不自研也不必要）；其余每一项都有明确的自研路线，但**收益普遍不高**，建议按"顺手清理 → 择机替换"处理，不设硬性期限。
4. **LiveKit 已彻底移除**（v2 报告中唯一 ✅ 工程项，M-C 完成），自研 WS 传输层成为默认，打断延迟实测 2.8–5.2ms。
5. **web 前端已是零依赖纯自研**（vanilla JS + canvas，无 CDN 引用，实测确认）。

**总体判定**：工程可自研面已基本收割完毕（传输层/web/封装层全部自研）；剩余不可绕过的硬绑定只有 **5 组模型权重**（MuseTalk unet、Whisper-tiny、SD-VAE、GPT-SoVITS 全家桶、人脸检测教师模型）——它们的共同解法是同一条长期线：**自训模型**。在那之前，权重按"资源"管理、代码按"自有"管理，主体功能 100% 可用。

## 二、Tier-1 逐项可行性分析（项目级上游工程）

### 2.1 GPT-SoVITS（thyagi/GPT-SoVITS 系）—— ⚠️ 新增核心项：代码可收编，权重有训练墙

**现状绑定面（实测）：**

| 层 | 现状 | 自研状态 |
|---|---|---|
| 调用面 | `voice/pool.py` 以 `sys.path` 注入 + `from GPT_SoVITS.TTS_infer_pack.TTS import TTS` 导入 | 接口唯一且窄（`TTS_Config` / `TTS.run` 生成器），已具备替换自由度 |
| 封装层 | [voice/worker.py](file:///e:/项目/LiveAvatar/src/liveavatar/voice/worker.py)（NvcWorker：角色权重不可变 + asyncio.Lock 串行推理 + CancelToken 协作取消）、[voice/pool.py](file:///e:/项目/LiveAvatar/src/liveavatar/voice/pool.py)、[voice/lease.py](file:///e:/项目/LiveAvatar/src/liveavatar/voice/lease.py)、[tts.py](file:///e:/项目/LiveAvatar/src/liveavatar/tts.py)（FakeTts 兼容适配器 + 流式接口） | ✅ **已是自己写的**，且解决了上游 api_v2 全局权重串扰问题 |
| 引擎代码 | `third_party/GPT_SoVITS/`（vendored，已提交；大资产走 `scripts/download_gptsovits.py`） | MIT 许可可自由改写；体量大（AR-GPT t2s / VITS v2Pro / BigVGAN / HuBERT / BERT / 文本前端），维护成本高 |
| **基础权重** | ~1.4GB 预训练模型（含 fasttext 语言检测 lid.176.bin） | ❌ 只能训练或保留 |

**自研替代路线：**

- **V-A 维持 vendored + 收编声明（推荐，成本 0–1 天）**：补一份 `third_party/GPT_SoVITS/README_自研声明.md`（来源、MIT 许可、修改清单、接口冻结承诺），与 MuseTalk 处理方式对齐。主体功能 100% 不变。
- **V-B 引擎收编为自有模块（1–2 周）**：把 `third_party/GPT_SoVITS` 迁入 `src/liveavatar/tts_engine/` 并做纯 Python 重构（去 sys.path hack、包内 import、裁剪 webui/训练代码只留推理），行为零变化。**收益是品牌与整洁，不是去依赖**——权重仍在。
- **V-C 自研 TTS（真替换）❌（现阶段）→ ⚠️（长期）**：TTS 比口型生成更深——中文文本前端（归一化/多音字 G2PW 消歧/多语种分词）是无穷边角 case 的纯逻辑工程，声学模型（少样本克隆 AR-GPT + VITS + BigVGAN）是数月 + 多卡 GPU 的训练工程，且质量回退风险大于 MuseTalk 自研。**不设路线图，仅作长期储备**；文本前端（zh_normalization ~2000 行）若未来做自研 TTS 可优先自写（无权重依赖，⚠️ 2–4 周）。

**结论**：⚠️ 代码层按 V-A→V-B 收编（与 MuseTalk 同模式），权重层是训练墙（❌）。**推荐 V-A 立即做，V-B 随 R1' 清理顺手做，V-C 不立项。**

### 2.2 MuseTalk —— ⚠️ 不变：代码已自研，权重待 R3 自训

与 v2 结论一致（见 2.4/2.5 联动）：推理代码在 `src/liveavatar/musetalk/` 已是自有模块，`AvatarWorker` 抽象把权重隔离在 worker 内。真正绑定的是 musetalkV15/unet.pth。替换 = R3 自训口型模型（1–2 月 + GPU，质量回退风险）。**本轮补充发现**：其"自有模块"中 `musetalk/models/` 源码未被 git 提交（见 §一.2 P0），需在 R1' 修复。

### 2.3 Whisper-tiny（transformers）+ sd-vae-ft-mse（diffusers）—— ⚠️ 与 2.2 联动，库依赖可单独剥离

**本轮实测绑定点收窄**：
- transformers 只用了 `WhisperModel` + `AutoFeatureExtractor`（[audio2feature.py](file:///e:/项目/LiveAvatar/src/liveavatar/musetalk/audio2feature.py)，且只用 encoder 前向）；
- diffusers 只用了 `AutoencoderKL.from_pretrained`（[vae.py](file:///e:/项目/LiveAvatar/src/liveavatar/musetalk/models/vae.py)）+ `UNet2DConditionModel` import（unet.py，仅配置读取，自研 UNet 类才是实际推理体）；
- PIL 仅 vae.py 一处（图像归一化）。

**自研替代路线（库依赖剥离，权重保留）**：
- 自研 `AutoencoderKL` 模块定义（纯 conv，~150 行 torch）+ diffusers 格式 state_dict key 映射加载 → 去 diffusers 依赖，**2–4 天**，需数值对齐验证（decode 输出与 diffusers 版 allclose）；
- 自研 whisper-tiny encoder 定义（公开架构，~200 行）+ 权重加载 → 去 transformers 依赖，**3–5 天**；
- PIL → numpy/cv2，**半天**。
- **评价**：⚠️ 全部可行，但本质是把"库依赖"换成"权重格式依赖"，省下的只是 pip 安装面。**建议降优先级，随 R3 自研模型连带解决**；若坚持先做，纳入 R2'。

### 2.4 MediaPipe Face Landmarker + OpenCV YuNet —— ❌→✅ R1 自研已在途（进度推进）

M0–M5 CPU 部分已全部完成（数据管线 / TinyFaceDetector / LandmarkNet5Self / 双后端切换 / face_accept 验收指标库 / mediapipe 降级为训练期教师 + 5 个隔离守卫测试）。**剩余全部阻塞在 GPU 空闲窗口**：数据集下载 → 教师伪标注 → M1/M2 训练 → M4 正式验收 → 默认后端切换。过渡期 legacy 后端保证主功能 100%。评级不变：❌→⚠️（自训可行，已在执行）。

### 2.5 ffmpeg（RTMP 可选 sink）—— ⚠️ 不变：不可自研，可裁剪

可选扩展功能，非主体。自研 WS 推流已覆盖主要分发场景；硬性 RTMP 需求保留 ffmpeg 二进制即可。

### 2.6 demo 素材 / 参考音频 —— ✅ 不变：自采替换

半天工作量，跑 `prepare_avatar.py` 即可去掉对 MuseTalk 仓库的数据依赖。

### 2.7 ~~LiveKit~~ —— ✅ 已完成移除

v2 报告的唯一 ✅ 工程项。M0–M6 完成 + M-C 彻底删除（engine、SDK、env 开关、守卫测试 `test_no_livekit.py`）。实测打断延迟 2.8–5.2ms（门禁 ≤90ms）。**本报告起不再列为依赖。**

## 三、Tier-2 逐项可行性分析（底层库/框架）

> 原则：numpy/torch 这类"基石"不自研也不必要；其余每项给出路线与工作量，按收益排序决定做不做。

| # | 库 | 实际使用面 | 评级 | 自研路线与工作量 | 建议 |
|---|---|---|---|---|---|
| 1 | numpy | 全项目数值内核 | ❌ | C 数值内核，不可也不必自研 | 保留 |
| 2 | torch / torchvision | 全部模型推理/训练 | ❌ | GPU 推理运行时，不可自研 | 保留 |
| 3 | diffusers | AutoencoderKL + UNet 配置（仅 musetalk） | ⚠️ | 自研 VAE 定义 + state_dict 加载，2–4 天（见 2.3） | 随 R3，或 R2' |
| 4 | transformers | Whisper-tiny encoder（仅 musetalk） | ⚠️ | 自研 encoder 定义 + 加载，3–5 天（见 2.3） | 随 R3，或 R2' |
| 5 | einops | **无引用（实测）** | ✅ | 无需自研——已是死依赖 | **R1' 直接从 extras 删除** |
| 6 | fastapi + uvicorn | REST ~6 端点 + 2 WS + StaticFiles | ⚠️ | 自研微 ASGI 路由（项目已有 ASGI receive loop 自研经验），1–2 周；健壮性/兼容风险由测试网承接 | 可行但不建议优先；publish/ 已模块化，将来切换面可控 |
| 7 | pydantic / pydantic-settings | config 校验 + API models | ⚠️ | dataclass + 手写校验，~1 周，收益低 | 不做，保留 |
| 8 | opencv (cv2) | 图像 IO/resize/颜色转换（runtime）、FaceDetectorYN、videoio（离线工具） | ❌ | 基础算子可 numpy 化但慢 5–10×（视频管线每帧调用）；FaceDetectorYN/videoio 无自研价值 | 保留 |
| 9 | websockets（客户端库） | realtime_asr_client 连外部 ASR + 测试 | ⚠️ | 自研 RFC6455 客户端 ~300–500 行（服务端 WS 已自研，经验同构），2–3 天 | R2' 可选 |
| 10 | dev 工具链（pytest / pytest-cov / pytest-timeout / httpx2 / ruff / mypy） | 测试与质量门禁 | ❌ | 非主体功能，无自研价值 | 保留 |

**web 前端**：`web/` 三个文件零外部依赖（无 CDN、无框架），✅ 已是自研终态。

### 4.2 分阶段路线（v3）

- **R1' 零风险清理（~1 周，CPU 即可）**：
  1. **P0 修复**：`.gitignore` 加 `!src/liveavatar/musetalk/models/` 例外（或改规则为 `/models`），把 vae.py/unet.py 真正提交入库；
  2. 从 `inference` extras 删除 einops（死依赖）；
  3. GPT-SoVITS V-A 收编声明（third_party README：来源/许可/接口冻结）；
  4. 自采素材替换 demo 素材；
  5. ffmpeg RTMP sink 降级为可选插件（文档声明即可）。
- **R2' 库依赖瘦身（可选，2–3 周，全部 CPU 可验证）**：diffusers → 自研 VAE 加载器（含 allclose 数值对齐测试）；transformers → 自研 whisper-tiny encoder；PIL → numpy；websockets 客户端 → 自研 RFC6455（可选）；fastapi/pydantic 自研**不纳入**（收益/风险比不划算，保留）。
- **R3 模型自研并行线（不变，GPU）**：R1 人脸（GPU 清单在途）→ R3 口型模型（第二个 AvatarWorker 接入）→ 远期 TTS（不立项，仅储备文本前端自研）。

### 4.3 验收标准（每阶段全量执行）

1. 模式 B：8s 音频 → 200 帧视频，0 丢帧 0 错误；
2. 全双工会话：TTS 流式合成 → 推流 → 浏览器观看 → epoch 打断（TTS ≤1 chunk、视频 ≤1 帧）→ VoicePool 租约隔离 → 降级链触发与恢复；
3. 全量测试 / ruff / mypy / coverage（≥80%）全绿，CI 三 Python 版本通过；
4. （R2' 专项）自研加载器与原库输出数值 allclose（VAE decode、Whisper encoder 特征）；
5. （R3 专项）自研模型与现权重同测试集 A/B 评审达标后才允许默认切换。
